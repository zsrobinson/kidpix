# Running the supplied original for reference captures

Investigated 2026-11-09. This note concerns the actual Mac trial in the mounted `KPD3DMac.dmg`, not another Kid Pix release. **The original application has not run here. No native screenshot, animation, audio, or interaction timing was verified during this investigation.**

The concrete local route is **UTM/QEMU PowerPC G4 emulation with a supplied, lawfully usable OS X 10.5 Leopard installer or existing compatible guest disk**. UTM's own compatibility table includes G4 guests with OS X 10.4 and 10.5. Tiger must reach the guide's 10.4.11 minimum. This is a documented guest-platform candidate, not an application compatibility test. It requires two presently missing prerequisites: a runnable emulator and the guest OS media. The Kid Pix installer itself is already available. [UTM Classic Mac OS compatibility](https://docs.getutm.app/guides/classic-macos/#compatibility), [bundled guide](../../artifacts/research/user-guide.txt), printed page 6.

For trustworthy real-time animation and audio latency, prefer a compatible physical Intel Mac running the guide-era OS X 10.6/10.7, if one can be supplied. A suitable G4 with 10.4.11/10.5 is another native execution candidate. No such machine was inspected or established as available. Emulated execution can still provide valuable original-program pixels, frame order, state transitions, and cancellation behavior, with its environment recorded explicitly.

## Evidence from this exact installer

- `artifacts/research/kidpix-original` is a 7,794,072-byte universal Mach-O with **i386** and **ppc_7400** slices. `file` and `lipo -detailed_info` confirm i386 at file offset `0x1000` (3,535,980 bytes) and PPC7400 at `0x361000` (4,251,032 bytes). SHA-256 is `a4d270edd09540a3a696a2b3e95f6dab29d52fd6bd6f1d3ed679b7990ed799a5`.
- Read-only decompression of the mounted installer's `Contents/Resources/Archive.zplist` and `Archive.zp` found `Contents/MacOS/Kid Pix` with **the identical size and SHA-256**. The archived app `Contents/Info.plist` identifies `com.mackiev.kidpix3d`, `CFBundleShortVersionString=2.2`, `CFBundleVersion=615`, and `CFBundleExecutable=Kid Pix`. These are payload values, not an About dialog observed at runtime.
- That app plist declares `LSMinimumSystemVersion=10.4.0`, with `RSystemVersionLow` and `RSystemVersionRequired` also containing `10.4.0`. The **bundled user guide instead specifies 10.4.11 or later, explicitly including 10.7 Lion**; use 10.4.11 as the supported floor. Neither the lower plist gate nor successful linkage would prove correct behavior on 10.4.0. Guide text lines 206–218 also specifies G4 700 MHz or faster / Intel Mac, 512 MB RAM, millions of colors, minimum 800×600 and recommended 1024×768. It gives approximately 350 MB for a minimum install requiring the disc at launch, or 2.2 GB for a full install. [Guide](../../artifacts/research/user-guide.txt).
- Both executable slices have ordinary `LC_LOAD_DYLIB` dependencies on **Carbon, QuickTime, QTKit, CoreVideo, AGL/OpenGL**, Cocoa/AppKit/Foundation, CoreServices/ApplicationServices, CoreAudio/AudioToolbox/AudioUnit and other system libraries. Neither slice has an `LC_LOAD_WEAK_DYLIB`, `LC_VERSION_MIN_MACOSX`, or `LC_BUILD_VERSION` command. The dylib *current-version numbers* reported by `otool -L` describe linked libraries; do not interpret them as the app's deployment-target OS version.
- Nine directly linked bundled frameworks were present in the payload and **each has both PPC and i386 slices**: `GData/A`, `SMKAudioFoundation/D`, `SMKCarbonKit/A`, `SMKCoreAdditions/D`, `SMKFoundation/A`, `SMKiAppsImport/C`, `SMKiMovieExport/A`, `SMKSubmitInfo/G`, `SMKUniPanel/D`. Their install names use `@executable_path/../Frameworks` or `@loader_path/../Frameworks`. Preserve the complete installed bundle, framework version directories/symlinks and resources; the standalone research executable is not an installable application. This check does not recursively certify every framework's dependencies or every optional plugin.
- The actual installer executable, `Kid Pix Installer.app/Contents/MacOS/Installer`, is also PPC/i386. The installer plist describes installer version 2.1/build 137 and product 2.2/build 615. Do not confuse installer and product versions.
- `hdiutil imageinfo KPD3DMac.dmg` reports UDZO/zlib compression, an Apple partition map and Apple_HFS volume, with 2,216,876,032 uncompressed bytes. This image supplies Kid Pix and libraries, **not an OS X installation**.

Reproduce the basic executable evidence without launching anything:

```sh
file artifacts/research/kidpix-original
lipo -detailed_info artifacts/research/kidpix-original
shasum -a 256 artifacts/research/kidpix-original
otool -arch i386 -L artifacts/research/kidpix-original
otool -arch ppc -L artifacts/research/kidpix-original
otool -arch i386 -l artifacts/research/kidpix-original
otool -arch ppc -l artifacts/research/kidpix-original
plutil -p '/Volumes/Kid Pix Deluxe 3D/Kid Pix Installer.app/Contents/Info.plist'
```

For payload paths and segment decoding, see [`app_resources()`](../../scripts/import-ui.py), lines 21–54. This investigation independently used its archive/segment algorithm in memory: Python `zlib.decompress`, Foundation `NSUnarchiver` through `/usr/bin/osascript -l JavaScript`, then selected `FilesList` entries. Python `plistlib` decoded the app plist; Mach-O fat headers supplied the framework architecture checks. No extracted app bundle was written or launched. The default Homebrew Python and `/usr/bin/python3` both failed `import Foundation`, so the repository's PyObjC-based importer was **not** rerun.

Useful binary addresses for later capture interpretation, all i386 virtual addresses:

- QuickTime drawing imports: `_QTNewGWorld` stub `0x00352f7b`, `_QTNewGWorldFromPtr` `0x00352f80`; `_EnterMovies` `0x00352472`, `_NewMovieFromFile` `0x00352d05`. [Import list](../../artifacts/research/imports.txt).
- Animation interval handler `0x0015a52c`, next-update scheduling `0x0015a2ed`, due check entry `0x00158988`, shared clock call `0x0015767d`, and `_Microseconds` call `0x001dfaa5`, followed by millisecond conversion near `0x001dfb9f`. These support intended 100 ms script intervals, not measured wall-clock delivery. [Disassembly](../../artifacts/research/disassembly-i386.txt), [timing interpretation](../reverse-engineering.md).
- Paper rendering's unresolved destination color-table path includes allocation entry `0x001ccbdd` and PixMap table access near `0x001d1f04`. Retain the existing palette uncertainty until actual guest output is captured. [Paper evidence and limits](../paper-canister.md).

## Which execution routes fit

**Current Apple Silicon host, hardware virtualization:** not a route to this binary. UTM requires matching guest/host architectures for virtualization, and its ordinary Apple Silicon macOS guest flow is macOS 12+ using Apple Virtualization. Those guests cannot supply the pre-Catalina 32-bit Mac environment: Apple states that 10.14 Mojave was the last macOS supporting 32-bit applications. ARM virtualization, nested virtualization, Linux Rosetta, or a modern ARM macOS IPSW does not substitute for the required legacy OS/frameworks. [UTM architecture requirements](https://docs.getutm.app/settings-qemu/system/#architecture), [UTM macOS guest installation](https://docs.getutm.app/guest-support/macos/#installation), [Apple 32-bit compatibility](https://support.apple.com/en-us/103076).

**Current host, PPC full-system emulation:** the best documented local candidate. UTM explicitly lists G4/OS X 10.4 and 10.5 with PMU configuration. QEMU documents the `qemu-system-ppc` / `mac99` PowerMac board and OpenBIOS firmware; upstream machine code selects a `7400_v2.9` CPU for the 32-bit target and supports one CPU. This matches the supplied application's PPC7400 slice at the architecture level. It does not certify Kid Pix, its QuickTime effects or GL paths. CPU translation is software emulation and is slower than matching-architecture virtualization; no throughput factor has been measured here. [UTM compatibility](https://docs.getutm.app/guides/classic-macos/#compatibility), [QEMU PowerMac board](https://www.qemu.org/docs/master/system/ppc/powermac.html), [QEMU `core99_machine_class_init`](https://github.com/qemu/qemu/blob/master/hw/ppc/mac_newworld.c), [UTM emulation distinction](https://getutm.app/).

**Current host, Intel full-system emulation:** QEMU/UTM can emulate x86 CPUs, but that alone does not establish a supported bootable legacy OS X configuration. No compatible guest, boot configuration or required firmware was supplied or tested. It offers no hardware-virtualization advantage over PPC on ARM and is a less direct starting point than the vendor-documented G4 guest. No patched guest, borrowed device identity, firmware/key extraction or licensing workaround is proposed. [UTM system architecture](https://docs.getutm.app/settings-qemu/system/#architecture).

**Parallels on Apple Silicon:** do not repeat the outdated blanket claim that it can never emulate x86. Current Parallels documentation describes an x86 emulator, but its documented candidates are Windows and Linux; it does not establish legacy Intel macOS support for this task. Nothing relevant was installed here. Buying/installing it is unnecessary for the identified PPC path. [Parallels x86 emulator scope](https://kb.parallels.com/en/130217), [supported guests](https://kb.parallels.com/en/124223).

**Physical compatible Mac:** strongest candidate for real-time UX capture because it avoids CPU/device emulation. The guide explicitly supports Intel Macs and OS X through Lion; select an OS that the particular Mac actually supports and preserve the original app version. Mojave's general 32-bit support is a compatibility ceiling, not proof that this particular 2012 bundle works there. A later Intel Mac unable to boot the old OS is not automatically suitable. [Bundled guide](../../artifacts/research/user-guide.txt), [Apple 32-bit boundary](https://support.apple.com/en-us/103076).

**Raspberry Pi / ordinary Linux or Windows / classic Mac OS 9:** none is an immediate execution environment for this Mach-O/Carbon/QuickTime bundle. A Pi would still need full-system PPC/x86 emulation and the same guest OS. A Windows edition would be a different binary requiring separate evidence. Classic-only emulators and a Mac OS 9 guest do not meet this app's OS X floor. These exclusions follow from the observed Mach-O architectures, linked Mac frameworks and bundled system requirements; no remote compatibility or performance test was performed.

## Concrete provisioning plan, once prerequisites are supplied

This is a proposed procedure; **none of these provisioning steps was executed**.

1. Supply a runnable macOS UTM build and lawfully usable **PPC-capable OS X 10.5 installer** or compatible existing guest disk. An Intel-only restore disc is unsuitable for the PPC route. Tiger is an alternative only with a path to **10.4.11**, including any required update media. Confirm the actual OS media/license permits the intended setup before provisioning; this investigation does not grant rights or propose bypasses.
2. Create a UTM **Emulate → Classic Mac OS → Power Macintosh G4** guest using the supplied media. Verify QEMU backend, PPC/G4 CPU, `mac99`, **PMU**, one vCPU and at least 512 MB RAM. Proposed working allocation: 1 GB RAM, 16 GB guest disk. Those allocations are planning choices, not tested performance settings. Use OS X's own disk utility for OS X media; UTM's generic classic guide also contains OS 9 installation steps that should not be blindly applied to OS X. Follow the current build's supported wizard/settings. [UTM guide](https://docs.getutm.app/guides/classic-macos/), [machine source](https://github.com/qemu/qemu/blob/master/hw/ppc/mac_newworld.c).
3. Keep the guest and any converted installer/capture output under an agreed `artifacts/t3/native-runtime/` location for this investigation. Give the guest no production shares or bridged networking; start with networking disabled. OS setup and Kid Pix UI capture do not require YouTube publishing or account logins. Do not assume modern guest-tools directory sharing works on Leopard.
4. Transfer the complete known installer image read-only. If UTM cannot consume the compressed DMG as removable media, Apple's installed `hdiutil(1)` documents conversion to a DVD/CD-R master. A future command is shown below. Attach the resulting `.cdr` as a removable IDE CD image, verify the guest sees **Kid Pix Deluxe 3D**, then run the **original installer inside the guest**, preferably Full Install. Keep its trial/activation behavior intact. Do not assemble a runnable app from the browser's converted assets. [Installed Apple `hdiutil(1)`, `convert` / `UDTO`; original install procedure in the guide](../../artifacts/research/user-guide.txt).

   ```sh
   mkdir -p artifacts/t3/native-runtime
   hdiutil convert KPD3DMac.dmg -format UDTO \
     -o artifacts/t3/native-runtime/kidpix-installer
   ```

5. Set the **guest display to 1024×768, millions of colors** and retain its color profile. Record actual mode, depth, profile, guest OS/build, emulator version/settings and installed app hash. Capture the framebuffer rather than assuming a scaled host window equals guest pixels. UTM distinguishes guest display hardware, scaling and Retina mode; its GPU-acceleration documentation lists specific supported guest-driver paths, not a blanket accelerated legacy OS X promise. Treat GL/QuickTime effect performance and correctness as acceptance checks. [UTM display settings](https://docs.getutm.app/settings-qemu/devices/display/).
6. Acceptance gate: launch to the actual Paint Zone, verify About/build 615, draw/undo, open paper, play one authored sound and one library movie, and record visible failures. A successful boot or About dialog alone is insufficient. If Screamer audio destabilizes boot, a separate sound-disabled diagnostic session can establish visual feasibility, but cannot certify audio-dependent completion. UTM documents Screamer instability. [UTM PPC troubleshooting](https://docs.getutm.app/guides/classic-macos/#ppc-startup-crashes-with-illegal-exception-or-hang-while-loading).

Missing prerequisites for the parent to resolve: emulator availability/install authorization; appropriate licensed OS X media or an existing guest; enough guest/capture storage; screen/system-audio capture permission if required. If real-time fidelity is the deciding requirement, also determine whether a compatible physical Mac can be supplied. No prerequisite request was sent from this task.

## Capture plan focused on animation and UX

**First record provenance, then motion, then comparison stills.** Original-program execution under an emulator should be labeled `original-emulated`; hardware execution should be labeled `original-hardware`. Extracted resources, disassembly interpretations and browser screenshots stay in their existing evidence categories.

- Preserve full raw captures and capture metadata in the isolated task directory. Record the binary SHA above, full-install/trial state, selected slice, guest OS/build, emulated machine/CPU/RAM/display/audio, host OS, capture tool/version/codec/frame rate, date, dropped-frame count and exact event recipe. Save screenshot dimensions and crop origin. Never overwrite native references with assembled resources or web captures.
- For stills, prefer a guest screenshot or emulator framebuffer dump that preserves exact guest pixels. QEMU's monitor provides `screendump` to PPM; that is a possible CLI backend capture mechanism, **not a claim that this UTM build exposes the monitor**. Convert losslessly to PNG, with no resizing or color adjustment, and preserve the raw source. A guest screenshot or verified unscaled OBS/host crop is the fallback. [QEMU monitor](https://www.qemu.org/docs/master/system/monitor.html).
- For motion, proposed acquisition is OBS at **60 fps**, lossless or visually lossless, no scene scaling, exact 1024×768 content crop plus raw full-window source, cursor included and separately identified. Inspect dropped frames and audio synchronization before using it. Sixty frames per second samples a 100 ms authored hold approximately six times; that sampling calculation does not mean native input latency is accurate to 1 ms. Keep recorder presentation timestamps, and log input-event times on the same declared clock when possible. Do not turn capture-frame counts into guest scheduler measurements without clock calibration.
- Run each interaction at least three times. Start from a declared selected tool/page state, move from a fixed outside point, enter the source region, hold for 1–2 seconds, then leave. Repeat with press/release inside, drag outside before release, rapid re-entry, crossing adjacent controls, selection change, Escape, window focus loss and modal interruption. Record event delivery/release coordinates; host trackpad feel alone is not evidence of the app's pointer rules.
- Prioritize **Undo Guy** authored sequences and undo/redo toggle; **Firehose rollover** (including whether it survives leave, associated with Easel `tSCR 1091`, MBTN row 19/word 12 = 294); **tool palette changes** from `Tp.MHK` MBTN 18400 (11–16 authored drawing groups at 100 ms); and **paper canister** open/close, selected texture replacement, rapid reopen, Escape, outside click and click pass-through. Source scripts identify tests to run, not outcomes already established. [Animation audit](../ui-animation-audit.md), [control evidence](../button-animation.md), [paper evidence](../paper-canister.md).
- Capture default paper and several selected textures as lossless stills throughout the opening sequence. Compare nontransparent grayscale samples to both recovered `tPAL 1000` decoding and the alternative current-port table hypothesis. Record guest depth/profile and the actual RGB samples. A movie screenshot with lossy compression or host color conversion cannot settle the CLUT question.
- Include held stationary strokes, moving strokes, release outside the page, tool/focus changes while held, undo immediately after completion, and modal/palette keyboard behavior. For timing runs, also record whether audio is enabled and whether audio completion gates the visible state. Defer microphone/camera-dependent tools until basic drawing/UI/movie/audio operation passes.
- Complete the ten existing static recipes in [`tests/browser/scenarios.js`](../../tests/browser/scenarios.js), using a new picture for each prescribed starting state and exact page coordinates. The app frame is **1024×768**, with the **720×542** page at **(164,67)**. Preserve larger desktop images and crop only; do not resize. [Existing reference workflow](../parity.md#capture-the-original).

Emulated CPU/device load, guest clocks, audio buffering, software GL, host input delivery and recorder frame loss can alter observed timing. Until calibrated, report **observed original-program behavior in the named guest** separately from **real-hardware timing**. Static 100 ms waits remain source evidence; a slow guest neither invalidates that constant nor proves authentic pacing. Do not adjust the web implementation's timing merely to match a struggling emulator.

```sh
npm run parity:reference -- paint-empty \
  artifacts/t3/native-runtime/paint-empty.png \
  --source 'original-emulated; Kid Pix 2.2/615; SHA256 a4d270edd09540a3a696a2b3e95f6dab29d52fd6bd6f1d3ed679b7990ed799a5; actual guest OS/build; actual UTM version/settings; actual capture date/method'
```

Replace the descriptive placeholders with measured values before running. Larger raw images may use `--crop x,y,1024,768`. The importer timestamp is import time, so put the actual acquisition date in `--source` and the raw manifest. There is currently no motion-reference ingestion API; parent-owned work would be needed to add one. Keep any future motion files and timestamp/event manifests isolated until that contract exists.
