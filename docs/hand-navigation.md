# Hand object navigation browser policy

Next (MBTN926 row5, command22355) and Back (row10, command22360) select one entry in the scene's **current serialized objects array order**. Existing renderable image, video and text records participate; animation records remain images with animation fields. This inclusion is a browser adaptation, not a translation of the native bitmap rebuild filter. Reorder immediately changes browser navigation direction. Restore, Undo/Redo and document replacement retain their existing selection policies; absent selection disables navigation.

`scene.navigation` supplies a read-only capability, separate count-based `canStep`, and identity. `scene.stepSelection(direction, expectedIdentity)` accepts only ±1 and the current identity. The scene recomputes position by actual selected identity, chooses exactly one destination, and rejects invalid/duplicate IDs or unrenderable destination records without scanning or editing them. Zero/absent/stale selection rejects; a selected singleton enables both controls and accepts a no-op. Two or more entries wrap in both directions. No second list, persisted field or global selection cache exists.

The identity includes document epoch, semantic mutation generation, selected ID, mode, playback and staging/gesture state. Presentation renders, artwork readiness, voice catalogs and font chrome do not advance it. Mutations and history restore retire held proposals, including a return to an earlier order or selection. Navigation targets alone include this generation: unrelated held formatting, voice and clipboard actions retain their existing identity rules. The idle capability performs no serialization, raster readback or canvas allocation and caches its immutable result.

Availability requires Hand, a valid selected scene owner, and an idle scene. Object drag, path mode, picture playback, scene suspension/staging, disposal, modal dialogs, project operations and a pending sticker transaction exclude the command. These are browser ownership guards, not a semantic name for native canvas+b4. A navigation control's own pointer/key contact does not disable itself. Motion and static fallback both recheck live capability/identity on release; the coordinator uses the same scene command. There are no additional keyboard shortcuts.

Selection steps retain every content record, including zero-unit and whitespace text, geometry/order, raster/scene/text clipboards, save/export representation and both history stacks. Pending ordinary typing can be committed only by the existing text owner. The resulting callback identity is captured before calling external history code and rechecked afterward, so reentrant replacement/reorder cancels the navigation continuation without restoring retired state. Navigation itself publishes no history. Visual updates change only selection classes and resize handles in place: media nodes, preview membership, playback ownership, editor nodes and focused chrome survive.
